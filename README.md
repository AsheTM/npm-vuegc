# vuegc

CLI to generate a **Vue 3** single-file component (`.vue`) in your project's `src/` folder: `<script setup>`, TypeScript, CSS pre-processors, props and events.

For **Vue 2**, use vuegc 1: `npm install -g vuegc@1` (see [Versions](#versions)).

## Install

``` sh
npm install -g vuegc
```

Or run it without installing: `npx vuegc --name HelloWorld`.

## Usage

Run it at the root of a Vue 3 project (the folder that contains `src/main.js` or `src/main.ts`, creating the app with `createApp`, and `src/App.vue`), e.g. a Vite or Vue CLI 5 project:

``` sh
vuegc --name HelloWorld.vue [--scoped [true|false]] [--style css] [--path components] [--blank] [--force] [--dry-run] [--no-template|--no-script|--no-style] [--props title,items] [--emits update,close] [--module] [--options] [--ts]
```

| Flag | Description | Default |
|---|---|---|
| `--name` | **Required.** Name of the component, with or without `.vue` | |
| `--style` | CSS pre-processor: `css`, `scss`, `sass` (indented syntax), `less` or `stylus` | `css` |
| `--scoped` | `scoped` attribute on `<style>` (`--scoped false` to remove it) | `true` |
| `--path` | Folder inside `src/` for the component, created if missing | `src/` |
| `--blank` | Empty template and style, without the demo content | `false` |
| `--force` | Overwrite the component if it already exists | `false` |
| `--dry-run` | Print the component instead of writing it; same checks as a real run | `false` |
| `--no-template`, `--no-script`, `--no-style` | Leave the section out (at least one must remain) | `false` |
| `--props` | Comma-separated prop names, e.g. `title,items`, declared as `title: null` (any type) | none |
| `--emits` | Comma-separated event names, e.g. `update:modelValue,close`: `defineEmits([...])` / `emits: [...]` | none |
| `--module` | CSS modules: `<style module>` and `:class="$style.root"` instead of `scoped` | `false` |
| `--options` | Options API (`export default { name, props, data, methods }`) instead of `<script setup>` | `false` |
| `--ts` | TypeScript: `lang="ts"`, typed `defineProps<{ … }>()` / `defineEmits<{ … }>()`, `defineComponent()` with `--options` | `false` |
| `--help`, `-h` | Show the help (also shown without any argument) | |

Examples:

``` sh
vuegc --name HelloWorld                                 # src/HelloWorld.vue
vuegc --name Button --path components/ui                # src/components/ui/Button.vue
vuegc --name Card --props title,items --emits close     # props and events
vuegc --name Card --ts --style scss --blank             # TypeScript, scss, empty
vuegc --name Card --options                             # Options API
```

An existing component is never overwritten without `--force`. On failure, `vuegc` prints the reason and exits with code `1`.

## Generated component

`vuegc --name HelloWorld` generates `src/HelloWorld.vue`:

``` vue
<template>
    <div id="HelloWorld"> Component <span>HelloWorld</span> generated by <a href="">VueGC</a> </div>
</template>

<script setup>
</script>

<style lang="css" scoped>
#HelloWorld {
    font-size: 16px;
    line-height: 150%;
}
span { font-weight: bold; }
a { font-style: italic; }
</style>
```

`vuegc --name Card --props title,items --emits update:modelValue --blank`:

``` vue
<template>
    <div></div>
</template>

<script setup>
const props = defineProps({
    title: null,
    items: null
});
const emit = defineEmits(["update:modelValue"]);
</script>

<style lang="css" scoped>
</style>
```

The same with `--ts`:

``` vue
<template>
    <div></div>
</template>

<script setup lang="ts">
const props = defineProps<{
    title?: unknown;
    items?: unknown;
}>();
const emit = defineEmits<{
    "update:modelValue": [...args: unknown[]];
}>();
</script>

<style lang="css" scoped>
</style>
```

## Use as a library

``` js
const { vuegc } = require("vuegc");

// Generates <cwd>/src/components/HelloWorld.vue and returns its path
vuegc({ name: "HelloWorld", style: "css", scoped: true, path: "components", blank: false, force: false, cwd: process.cwd() });
```

Every CLI flag has an option: `style`, `scoped`, `path`, `blank`, `force`, `dryRun`, `noTemplate`, `noScript`, `noStyle`, `props` and `emits` (arrays), `cssModule` (`--module`), `optionsApi` (`--options`), `ts`, plus `cwd`.

On failure, `vuegc()` throws instead of exiting; `errorHandler(err)` prints the same message as the CLI and exits.

**TypeScript**: types are included (`vuegc.d.ts`), nothing to install:

``` ts
import { vuegc, type VuegcOptions } from "vuegc";

const options: VuegcOptions = { name: "Card", style: "less", props: ["title"] };
const file: string = vuegc(options);
```

## Versions

| vuegc | Vue | Install |
|---|---|---|
| 1.x | Vue 2 | `npm install -g vuegc@1` |
| 2.x | Vue 3 | `npm install -g vuegc` |

vuegc 2 refuses a Vue 2 project (`new Vue`) and points to vuegc 1.

See the [CHANGELOG](CHANGELOG.md) for the details of each version.

### Migrating from 1.x

| 1.x | 2.x | To get the 1.x output |
|---|---|---|
| Vue 2 projects | Vue 3 projects only | stay on `vuegc@1` for Vue 2 |
| `scss` by default | `css` by default | `--style scss` |
| Options API (`export default { … }`) | `<script setup>` | `--options` |

So in a Vue 3 project, `vuegc --name Card --options --style scss` generates what vuegc 1 generated.

## Development

``` sh
npm install
npm test            # run the tests once
npm run test:watch  # re-run on every change
```

Tests use [Vitest](https://vitest.dev) (Node 22.12+ or 24 for development):

- CLI tests create a temporary Vue project, run `vuegc` in it, and check the output, the exit code and the generated file.
- Library tests call `vuegc()` and `errorHandler()` directly, with mocks for `console.log` and `process.exit`.
- Snapshot tests lock the generated output (`npx vitest run -u` to update them on purpose).
- Type tests (`test/*.test-d.ts`) check `vuegc.d.ts` with TypeScript, so the types can't drift from the code.
