# vuegc

CLI to generate a **Vue 2** single-file component (`.vue`) in your project's `src/` folder.

## Install

``` sh
npm install -g vuegc
```

Or run it without installing: `npx vuegc --name HelloWorld`.

## Usage

Run it at the root of a Vue project (the folder that contains `src/main.js` and `src/App.vue`):

``` sh
vuegc --name HelloWorld.vue [--scoped [true|false]] [--style css] [--path components] [--blank] [--force] [--dry-run] [--no-template|--no-script|--no-style] [--props title,items]
```

| Flag | Description | Default |
|---|---|---|
| `--name` | **Required.** Name of the component, with or without `.vue` | |
| `--style` | CSS pre-processor: `css`, `scss` or `stylus` | `scss` |
| `--scoped` | `scoped` attribute on `<style>` (`--scoped false` to remove it) | `true` |
| `--path` | Folder inside `src/` for the component, created if missing | `src/` |
| `--blank` | Empty template and style, without the demo content | `false` |
| `--force` | Overwrite the component if it already exists | `false` |
| `--dry-run` | Print the component instead of writing it; same checks as a real run | `false` |
| `--no-template`, `--no-script`, `--no-style` | Leave the section out (at least one must remain) | `false` |
| `--props` | Comma-separated prop names, e.g. `title,items`, declared as `title: null` (any type) | none |
| `--help`, `-h` | Show the help (also shown without any argument) | |

Examples:

``` sh
vuegc --name HelloWorld                         # src/HelloWorld.vue
vuegc --name Button --path components/ui        # src/components/ui/Button.vue
vuegc --name Card --style css --scoped false    # plain CSS, not scoped
vuegc --name Card --blank --force               # regenerate Card.vue, empty
```

An existing component is never overwritten without `--force`. On failure, `vuegc` prints the reason and exits with code `1`.

## Generated component

`vuegc --name HelloWorld` generates `src/HelloWorld.vue`:

``` vue
<template>
    <div id="HelloWorld"> Component <span>HelloWorld</span> generated by <a href="">VueGC</a> </div>
</template>

<script>
export default {
    name: "HelloWorld",
    props: { },
    data() {
        return { };
    },
    methods: { }
}
</script>

<style lang="scss" scoped>
#HelloWorld {
    font-size: 16px;
    line-height: 150%;

    span { font-weight: bold; }
    a { font-style: italic; }
}
</style>
```

With `--blank`:

``` vue
<template>
    <div></div>
</template>

<script>
export default {
    name: "HelloWorld",
    props: { },
    data() {
        return { };
    },
    methods: { }
}
</script>

<style lang="scss" scoped>
</style>
```

## Use as a library

``` js
const { vuegc } = require("vuegc");

// Generates <cwd>/src/components/HelloWorld.vue and returns its path
vuegc({ name: "HelloWorld", style: "css", scoped: true, path: "components", blank: false, force: false, cwd: process.cwd() });
```

On failure, `vuegc()` throws instead of exiting; `errorHandler(err)` prints the same message as the CLI and exits.

## Development

``` sh
npm install
npm test            # run the tests once
npm run test:watch  # re-run on every change
```

Tests use [Vitest](https://vitest.dev) (Node 22.12+ or 24 for development):

- CLI tests create a temporary Vue project, run `vuegc` in it, and check the output, the exit code and the generated file.
- Library tests call `vuegc()` and `errorHandler()` directly, with mocks for `console.log` and `process.exit`.
